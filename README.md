# フィールドノート（現地調査用 Web 地図メモ）

スマホのブラウザで開いて使う、現地調査（フィールドワーク）用の地図アプリです。
現在地を見ながら地図タイルを切り替え、地点ごとにメモ・写真を記録し、端末のファイル（JSON など）に書き出せます。
ビルド不要の静的ファイル（HTML/CSS/JS）だけで動きます。対象は日本国内。

## 主な機能

| 機能 | 内容 |
|---|---|
| 現在地 | GPS の現在地・精度円・端末の向き（コーン表示）。◎ボタンで現在地へ移動、もう一度押すと追従モード |
| ステータス表示 | 緯度経度・精度・標高（地理院 DEM）・地域メッシュコード（3次）・住所（地理院 逆ジオコーダ）。タップで座標コピー |
| 地図切替 | ベース：**地理院 Vector**（ベクトルタイル）／地理院 標準／淡色／写真（最新・1974-78・1961-69・1945-50）／色別標高図／陰影起伏図／OSM |
| 地理院 Vector | 地理院の最適化ベクトルタイルを表示。「地図の切替」の子画面で **表示する項目**（注記・記号・道路・鉄道・建物・水部・等高線・地形表記・行政界・構造物・送電線。「シンプル」「地形を見る」「まち歩き」のまとめ選択も）と **スタイル**（標準・淡色・Ivory・Emberline・Bright Interlude・Vertical Dialogue・墨・Night）を選べる |
| PDF・画像の地図 | 河川整備計画などの PDF（ファイルまたは URL）や地図の画像（ファイル選択・コピーした画像の貼り付け・URL）から地図部分を切り出して、3 点以上の対応点で位置合わせ（ジオリファレンス）して重ねる。地図の切替パネルで表示／非表示・透明度・モノクロ・白を透過を切替。タップするとポップアップから参照 URL（元の PDF の該当ページなど）を開ける。参照 URL は後から設定・変更できる |
| 印刷・画像出力 | 用紙（A5・A4・B4・A3）・向き・縮尺を選び、地図の上の枠で範囲を合わせて、**PDF・PNG・印刷**で出力。方位記号・スケールバーを配置し、凡例は任意。印刷するレイヤ（背景・重ねる地図・1m標高・PDF/画像の地図・軌跡・メモ）を選べる |
| データを重ねる | **東京都 緑のオープンデータ**（公園・樹林地・農地・街路樹・水系など。配色と凡例は都の QGIS レイヤ定義どおり）、**不動産情報ライブラリ API** の 33 種のデータ（用途地域・洪水浸水想定・学校・地価公示など）、**e-Stat API** の統計表（市区町村・都道府県・地域メッシュで塗り分け）を、WebGL でまとめて描いて軽く重ねる。地物をタップすると属性を表示、凡例は地図の右下に自動で出る |
| ファイルを重ねる | GeoJSON・KML・jSTAT MAP の .gsf・Parquet / GeoParquet・基盤地図情報（基本項目の ZIP / XML）を地図に重ねる。属性表（CSV など）をキーで結合してから重ねることも、属性で色分け・ラベル表示することもできる |
| 地点をまとめて入力 | 「緯度, 経度, 名称」を 1 行ずつ貼り付けて、まとめてメモにする（調査予定地のリストなど） |
| 1m標高（段彩） | 国土地理院の 1m 標高タイル（DEM1A）を端末で色分け。色の範囲は「表示中の範囲に自動で合わせる」か手動、段彩の間隔（なめらか／0.5〜10m）、色（スペクトル・地形・エディトリアル・モノクロ）、陰影の強さを「地図の切替」の子画面で設定。地図の左下に凡例。1m がない所（水面・未整備の地域）は 5m・10m で補完 |
| 重ね合わせ | 陰影起伏・傾斜量図・色別標高図・治水地形分類図・土地条件図・明治期の低湿地、重ねるハザードマップ（洪水浸水想定〔想定最大・計画規模〕・浸水継続時間・家屋倒壊等氾濫想定区域〔氾濫流・河岸侵食〕・内水・高潮・津波・土砂災害警戒区域 3 種・雪崩危険箇所）。透過度スライダー付き、ハザードは「凡例」で凡例画像を表示 |
| その他のレイヤ | 「地図の切替」→「その他のレイヤ」：今昔マップ on the web（全国 59 地域の旧版地形図）・迅速測図（明治初期の関東）・地形分類（自然地形・人工地形。タップで説明と災害リスク）・活断層図・Wikipedia / Wikidata の周辺の記事・アメダス・降水ナウキャスト・ジャパンサーチ（この付近の資料） |
| 2 つの地図を比べる | 任意の 2 つの地図（背景・重ねる地図・今昔マップの各時期・迅速測図・地形分類など）を左右に並べ、境目をドラッグして見比べる |
| 標高断面図 | 計測した線や軌跡に沿って、標高タイルから断面図を描く（距離・高低差・登り下り・最大傾斜。グラフをなぞると地図上に位置を表示） |
| 写真をまとめて読み込む | 撮影位置（EXIF の位置情報）付きの写真から、その場所に写真メモを作る。近い場所で続けて撮ったものは 1 つにまとめる |
| 日の出・日の入り | ステータス欄に小さく常に表示（現在地または地図の中心で計算。日没まで 3 時間を切ると残り時間も） |
| 地図の回転 | 2 本指で地図を回せる。回したときだけ出る方位磁石ボタンで北を上に戻す（印刷・2 つの地図の比較の間は北が上） |
| 複数人の調査 | ほかの人が書き出した ZIP / JSON を「ほかの人のデータとして追加」で取り込む（自分のメモは変えず、新しい番号と記録者名を付けて追加。同じファイルの二重取り込みはしない）。ピンと軌跡は「カテゴリで色分け」と「記録者で色分け」を切り替えられる |
| ピンを動かす | ピンのポップアップの「位置を直す」で、ピンをドラッグして位置を直すモードに（元に戻す可。最初の位置はメモに残す） |
| GPS・方位の補正 | 任意。現在地ボタンの長押しか「設定」から：地図で正しい位置を指定してずれを直す・測位を数秒平均してメモを作る・精度の悪い測位を使わない・コンパスの向きを直す |
| 撮影 | 下の「撮影」ボタンでカメラが起動。撮った写真はその場所の写真メモとして**端末内に保存**され、地図上にサムネイルで表示（ズーム15以上。撮影方向があれば青い矢印）。タップで全画面表示・左右スワイプで切替・「保存」で端末の写真アプリ等へ |
| メモ | 「現在地にメモ」「中心にメモ」（十字線位置）・地図の長押し で作成。タイトル／カテゴリ（色分け）／本文／タグ／写真（「撮影して追加」「フォルダの画像を追加」）／撮影方向（コンパス） |
| 聞き取り | メモ画面の「聞き取りを開始」で録音と書き起こし。文字はメモ欄に追記。モードは「録音＋書き起こし」「録音のみ」「書き起こしのみ」。録音は端末内に保存され、メモのポップアップで再生、ZIP に `audio/` として入る。各録音の「書き起こす」で、録音からあとで書き起こすこともできる（端末内で処理） |
| カテゴリ編集 | メモ画面（カテゴリの「＋ 追加」「編集」）・一覧（「カテゴリ編集」）・設定で、追加・名前変更（メモも一括で変わる）・色の変更・並び替え・削除（メモは別のカテゴリへ移す） |
| 自動付与 | 通し番号・日時・座標・GPS 精度・GPS 高度・DEM 標高・住所・メッシュコード・表示中の地図・調査名・記録者 |
| 一覧 | キーワード・カテゴリで絞り込み、新しい順／番号順／近い順。現在地からの距離と方向（矢印は端末の向き基準）。「写真」タブで写真の一覧 |
| まとめて整理 | 一覧の「選択して整理」でメモにチェックを付け（「表示中を全選択」で絞り込み結果をまとめて選択も可）、カテゴリ変更・タグを付ける／外す・地図で表示（選んだメモを強調）・選んだメモだけ書き出し（ZIP／GeoJSON／CSV）・削除を一度に実行 |
| 軌跡 | 歩いたルートを記録（記録中は画面消灯を防止）。GPX / GeoJSON / JSON に含めて書き出し。記録した軌跡は「一覧」のメモの下で表示の切り替え・削除ができる |
| 計測 | タップした点の距離・面積・区間方位。「断面図」で標高断面図 |
| 地名検索 | 地理院の地名検索 API。`35.68, 139.76` のような座標入力にも対応 |
| 書き出し | **ZIP（JSON＋写真ファイル）**／JSON（写真の base64 埋め込みも可）／GeoJSON（QGIS 等）／CSV（Excel 用 BOM 付き）／GPX。「保存」＝ダウンロード、「共有…」＝OS の共有シート（iPhone は「ファイルに保存」） |
| 読み込み | 書き出した ZIP / JSON / GeoJSON を統合（同じ ID は更新日時が新しい方を採用）。複数端末・複数人のデータをまとめるのにも |
| GPX 取り込み | GPSLogger などの GPS ロガーアプリで記録した GPX を軌跡として取り込み、地図に表示（途切れ＝セグメントも保持）。GPX 内の地点（wpt）はメモになる。同じファイルを二重に読み込んでも重複しない。複数ファイルをまとめて選択可 |
| オフライン | アプリ本体と表示した地図タイルを自動キャッシュ。「表示範囲の地図を端末に保存」で事前ダウンロードも可能（上限 1500 枚） |
| ホーム画面に追加 | PWA 対応。全画面のアプリとして起動できる |

データ（写真を含む）はすべて端末内（ブラウザの IndexedDB）に保存され、外部サーバーには送信しません
（標高・住所・地名検索のために座標を国土地理院の API に問い合わせる通信のみ発生します）。

## スマホで使うには（HTTPS が必須）

ブラウザの位置情報・方位センサーは **HTTPS** でないと使えません。

### GitHub Pages で公開（おすすめ）

1. GitHub のリポジトリ **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする
2. `main` に push される（または Actions タブから「Deploy to GitHub Pages」を手動実行する）と
   `https://yusa-san.github.io/field_note/` で公開される
3. スマホで開き、共有メニューから「ホーム画面に追加」

※ 非公開リポジトリで Pages を使うには有料プランが必要です。Netlify / Cloudflare Pages などにこのリポジトリのファイルをそのまま置いても動きます。

### PC で動作確認

```bash
python3 -m http.server 8000
```

`http://localhost:8000/` を開く（localhost は HTTPS でなくても位置情報が使えます。同じ Wi-Fi のスマホから IP アドレスで開いた場合は HTTP なので位置情報は使えません）。

## 現地での使い方のコツ

- 調査前に「保存/設定」で **調査名・記録者** を入れておくと、メモとファイル名に記録されます。
- 電波の弱い場所に行く前に、Wi-Fi 下で対象範囲を表示 → 「表示範囲の地図を端末に保存」。
- GPS の位置がずれているときは、✚（十字線）を出して地図を動かし「中心にメモ」。既存メモも編集画面の「位置を地図中心へ」で修正できます。
- 軌跡記録中は画面を開いたままにしてください（ブラウザの制約で、画面オフやアプリ切替中は位置を取れません）。画面を消して長時間歩くときは、下の「GPS ロガーアプリと併用する」の方法がおすすめです。
- 調査の区切りごとに **JSON を書き出す**（「保存/設定」ボタンの赤い ! は未書き出しのメモがある印）。ブラウザのデータ削除や「ホーム画面に追加」したアプリの削除で端末内のデータは消えます。
- iPhone では書き出しは「共有…」→「ファイルに保存」が確実です。
- 聞き取りの書き起こしには 2 つの方式があります。
  - **その場で書き起こす**（「書き起こしのみ」、PC などの「録音＋書き起こし」）：ブラウザの音声認識を使うので通信が必要で、音声は認識のためにブラウザの提供元（Chrome なら Google）に送られます。
  - **録音から端末内で書き起こす**（Android の「録音＋書き起こし」、各録音の「書き起こす」ボタン）：Android の Chrome は録音とブラウザの音声認識を同時に使えないため、Android では録音を優先し、停止後に端末内の音声認識モデル（Whisper）で書き起こします。音声は外部に送りません。最初の 1 回だけモデルをダウンロードします（「保存/設定」で選択：高精度 約 250MB／軽量 約 80MB。「自動」は GPU が使える端末で高精度）。以後はオフラインでも使えます。処理時間は端末の性能しだいで、録音の長さの数倍かかることがあります。
  - 録音中は画面が消えないようにしています
- 写真は既定で撮影したファイルをそのまま（EXIF の撮影日時・位置情報も含めて）保存します。容量が気になる場合は「保存/設定」→「写真の保存サイズ」で縮小保存にできます。「撮影後にメモ入力を開く」をオンにすると、撮影のたびにメモ欄が開きます。
- ブラウザのカメラ機能で撮った写真は、端末の写真アプリには自動では入りません（このアプリの中にだけ保存されます）。写真アプリにも残したいときは、写真を開いて「保存」を押してください。

## GPS ロガーアプリと併用する（画面オフでも経路を記録）

Web アプリはブラウザの制約でバックグラウンドの位置記録ができないため、経路は専用アプリに任せて後から取り込みます。Android の例：

1. [GPSLogger](https://gpslogger.app/)（無料・オープンソース。Google Play / F-Droid）をインストール
2. GPSLogger の設定 →「ログの詳細設定」で **GPX に記録** をオン。記録間隔は徒歩なら 5 秒程度
3. 調査開始時に GPSLogger で記録開始 → 画面を消して歩いてよい（写真やメモはフィールドノートで）
4. 終わったら GPSLogger で記録停止。GPX ファイルは端末の `Download/GPSLogger`（または `Android/data/com.mendhak.gpslogger/files`）に保存される
5. フィールドノートの「保存/設定」→「読み込み」→「メモ・軌跡を読み込む」で GPX を選ぶ → 軌跡が地図に表示され、以後 ZIP 等の書き出しにも含まれる。取り込んだ軌跡は「一覧」のメモの下に並び、表示の切り替え・削除ができる

電池の最適化が強い機種（Xiaomi・OPPO など）では、GPSLogger を「電池の最適化」の対象外にしておくと記録が途切れにくくなります。

## PDF・画像の地図を重ねる（ジオリファレンス）

1. 「地図の切替」→ 一番下の「＋ PDF・画像から地図を追加」
2. **PDF を選ぶ**／**画像を選ぶ**／**画像を貼り付け**／**URL を入力**して読み込む
   - 画像の貼り付け：ほかのアプリでコピーした画像を「コピーした画像を貼り付け」ボタンで読み込みます。ボタンが使えない端末では、点線の欄を長押しして「貼り付け」（PC はクリックして Ctrl+V）
   - URL は PDF・画像のどちらでも読み込めます。ファイル選択や貼り付けのときも、欄に元の資料の URL を入れておくと参照 URL（ポップアップのリンク先）になります。後から「名前・参照 URL」で設定・変更もできます
   - 官公庁のサイトの多くは、他のサイト上のページからファイルを直接読み込むことを許可していません（CORS）。その場合は案内に従い、ファイルを開いて端末にダウンロード →「ダウンロードしたファイルを選ぶ」。入力した URL は参照 URL として残ります
   - 自前の CORS プロキシがあれば「保存/設定」に登録すると URL だけで読み込めます（`{url}` が元の URL に置き換わります）
3. PDF の場合は、地図が載っている**ページを選ぶ**（サムネイル一覧）。画像の場合はこの手順はありません
4. **切り出し**：オレンジの枠で地図の部分を囲む（凡例や余白を外す）。長辺 最大 4000px で描画し直します
5. **位置合わせ**：上が PDF の画像、下が地図。どちらもピンチで拡大できます
   - 交差点・橋・河川の合流点など、両方で分かる場所を「画像をタップ → 地図をタップ」の順に。3 点以上で計算されます。下の地図は地名検索で PDF の場所へ移動できます
   - 4 点目からは地図上に予測位置（点線）が出るので、ドラッグで合わせるだけ
   - 4 点以上で誤差（RMS, m）と点ごとの誤差が表示されます。大きい点はドラッグで直すか削除
   - 変換は「アフィン（推奨）」と「射影（4 点以上・写真や斜めに写った図向け）」から選択。「重ねて確認」で下の地図に重ねて確認
   - **部分ごとに合わせる（ゆがんだ地図向け）**：手描きの概略図や縮尺が場所によって違う図など、3〜4 点では全体が合わないときにオン。画像を細かい格子に分け、部分ごとに近くの対応点で合わせます。4 点以上必要で、地図全体に散らばるよう 8〜20 点ほど置くのがおすすめ
     - 「なめらか（推奨）」：すべての点をなめらかに通る面（薄板スプライン）で補間。ゆがみがなだらかな図向け
     - 「近くの点を重視」：各部分を近くの点だけで合わせる。ゆがみが不規則な図や、点の精度にばらつきがあるとき向け
     - 表示される誤差は「1 点抜き検証誤差」（各点を他の点だけで予測したときのずれ）。値が飛び抜けて大きい点は置き間違いの可能性があります
     - 部分ごとの位置合わせではワールドファイルは付きません（data.json に対応点と格子の座標が入ります）
6. 「保存」で地図に追加。以後「地図の切替」の「PDF・画像から追加した地図」で、表示・透明度・モノクロ・白を透過（紙の白い背景を透明にして下の地図と重ねる）・範囲へ移動・位置合わせのやり直し・名前と参照 URL の編集・削除ができます

### ラスタデータ（GeoTIFF）として保存

位置合わせした PDF 地図は、**位置合わせ済みの GeoTIFF**（北が上に描き直したラスタ、EPSG:3857、地図の外は透明）として保存できます。アフィン・射影・部分ごと、どの方式でも作れ、QGIS・ArcGIS などにドラッグするだけで正しい位置に重なります。

- 1 枚ずつ：「地図の切替」→ PDF 地図の「GeoTIFF 保存」
- まとめて：ZIP の書き出しに `overlays/pdfmap_01_georef.tif` として入る
- 解像度は元画像の細かさに合わせて自動で決まります（スマホのメモリに収まるよう、最大およそ 1400 万画素）。地図の白い部分なども含めた元の色のまま保存されます（モノクロ・白を透過は表示用の設定なので反映しません）

ZIP には元の切り出し画像 `overlays/pdfmap_01.jpg` と対応点も入り（全体のアフィン変換ならワールドファイル `.jgw` + `.prj` も付く）、ZIP を読み込むと位置合わせ済みの状態で復元されます。

## データを重ねる（緑・不動産情報ライブラリ・e-Stat）

「地図の切替」→「データを重ねる」から使います。どれも MapLibre GL（WebGL）の 1 枚の地図にまとめて描くので、数万件の地物でも動きが軽く、地物をタップすると属性が出ます。凡例は地図の右下に自動で出て（「凡例」でたためます）、印刷・PDF 出力にも入ります。

### 東京都 緑のオープンデータ

東京都都市整備局の「緑のオープンデータ（GISデータ）」の 14 ファイル・57 レイヤを、分類（公園緑地・農地・街路樹・崖線・丘陵地/山地・民間開発等・水系・都市計画法等・自然公園/条例等・樹林地・公共施設の緑）ごとに表示します。配色・重なり順・点や線の大きさは、都が配布している QGIS のレイヤ定義（`tokyo_green_open_data.qlr`）に合わせています。

元データは合計約 1.1 GB のシェープファイルなので、そのままではスマホで扱えません。`tools/build_green.py` で 1 つの **PMTiles**（ベクトルタイルを 1 ファイルにまとめたもの）に変換し、表示している範囲・ズームの部分だけを読み込みます。GitHub Pages への公開時に Actions が自動で作ります（初回は 20〜30 分。以後はキャッシュを使い、データを更新したいときは Actions の「Run workflow」で「作り直す」にチェック）。一度見た範囲は端末に残ります。

### 不動産情報ライブラリ（国土数値情報・都市計画決定 GIS など）

[不動産情報ライブラリ](https://www.reinfolib.mlit.go.jp/) の API のうち、地図のタイルとして取得できる 33 種（都市計画区域・用途地域・立地適正化計画・防火地域・地区計画・都市計画道路・小中学校区・学校・保育園等・医療機関・福祉施設・駅別乗降客数・図書館・役場・将来推計人口 250m メッシュ・人口集中地区・自然公園・災害危険区域・大規模盛土・地すべり防止地区・急傾斜地・液状化・洪水/高潮/津波浸水想定・土砂災害警戒区域・指定緊急避難場所・災害履歴・取引価格・地価公示/地価調査など）を選んで重ねられます。

- 色分けする項目は選べます（用途地域は慣用の配色、浸水深などは段階の配色。数値の項目は自動で段階に分けます）。凡例は表示中の範囲の区分から作ります
- 取引価格（XPT001）は取引時期、地価公示（XPT002）は年が必須です（初期値あり）
- 各 API には表示できるズームの下限（11・13・14 など）があります

この API は **ブラウザから直接呼べない**（CORS に対応していない・API キーを公開できない）ため、API キーを預けた**中継サーバ**が必要です（下記）。

### e-Stat（政府統計）

e-Stat API で統計表を検索し、表章項目・分類・時点を選んで、**市区町村・都道府県・地域メッシュ**の単位で塗り分けます（5 段階・同数分割）。市区町村の境界は [Geoshape 市区町村界データセット](https://geoshape.ex.nii.ac.jp/city/)（2023 年 1 月 1 日、国土数値情報 行政区域を加工）を使い、都道府県を 1 つ選ぶと細かい境界、全国にすると粗い境界になります。地域メッシュは境界データが不要で、メッシュコードから四角形を作ります。小地域（町丁・字）は境界が API で配布されていないため対象外です。

- e-Stat のアプリケーション ID（ユーザー登録で無料発行）をアプリの設定に入れるか、中継サーバに預けます
- 3000 地域以下の結果は値を端末に保存し、次回はすぐに表示します

このサービスは、政府統計総合窓口(e-Stat)の API 機能を使用していますが、サービスの内容は国によって保証されたものではありません。

### ファイルを重ねる（GeoJSON・KML・.gsf・GeoParquet・基盤地図情報）

「データを重ねる」の「＋ ファイルを重ねる」、または「保存・設定」→「読み込み」から使います。読み込んだデータは端末の中だけに保存され、外部には送信しません。

| 形式 | 内容 |
|---|---|
| GeoJSON（.geojson・.json） | 経緯度（WGS84・JGD2011）のもの |
| KML | 点・線・面と、名前・説明・ExtendedData の属性 |
| jSTAT MAP の .gsf | 地域の形と属性。jSTAT MAP の階級区分（色分け）が入っていれば、同じ階級と色で塗り分け |
| Parquet / GeoParquet | GeoParquet の geo メタデータ（WKB・GeoArrow）、geometry 列（WKB・WKT・GeoJSON）、または lat・lon 列から図形を作る。先頭 5 万行まで。解析ライブラリ（hyparquet）は初回だけ通信して読み込む |
| 基盤地図情報（基本項目） | ダウンロードした ZIP（入れ子の ZIP も可）または XML。建築物・道路・鉄道・水部・行政区画・等高線・標高点・基準点などを項目別に表示（数値標高モデルは対象外） |

- **属性表の結合**：「属性表（CSV など）を結合してから重ねる」にチェックして図形のファイルを選び、続けて表（CSV・TSV・JSON・Parquet・.gsf・KML）を選びます。キーの列は値の一致が多い組み合わせを自動で提案します。図形側を基準にした左結合で、表側に同じキーが複数あるときは最初の 1 行を使います。照合は前後の空白・大文字小文字・数値の 0 埋めの違いを無視します（厳密な照合にも切り替え可）
- **色分け・ラベル**：属性を選ぶと、文字はカテゴリ別、数値は 5 段階に塗り分けます。ラベルにする属性も選べます
- 上限はスマホで扱える量の目安として、地物 30 万件・頂点 300 万点です

.gsf・KML・基盤地図情報の読み取りと Parquet の図形の解釈は、Vector Studio v3.4 の取込パーサを移植したものです。.gsf の形状の形式は公開仕様ではない（解析による）ため、読めないファイルがあり得ます。

### Vector Studio との連携

- **スタイル JSON**：Vector Studio で作ったスタイルを地理院 Vector のスタイルとして読み込めます（「地理院 Vector のスタイル」の項）
- **範囲ファイル**：印刷の設定の「範囲を保存」で、今の印刷範囲を Vector Studio と同じ範囲ファイル（`vector-studio-range_*.geojson`）に保存できます。「範囲を読み込む」は Vector Studio の範囲ファイルのほか、GeoJSON・KML・.gsf の全体を囲む範囲を読み込み、その範囲が収まる縮尺と向きにします
- **地理院 Vector の最新データ**：「スタイル」の画面で、データを「最新（2026-04・PMTiles）」と「従来（2023-10・XYZ）」から選べます。最新のデータも、一度表示した範囲と「表示範囲の地図を端末に保存」で保存した範囲は端末に残ります
- **標高**：メモの標高と画面上の標高は、国土地理院の標高タイルから読みます（1m 標高があればその値、なければ 5m・10m）。一度読んだ範囲はオフラインでも使えます

### 不動産情報ライブラリ・e-Stat の中継サーバ（Cloudflare Workers・無料枠で可）

`tools/proxy-worker.js` を Cloudflare Workers に置きます。

1. Cloudflare ダッシュボード →「Workers & Pages」→「Create」→「Create Worker」（名前は例：`fieldnote-proxy`）→「Deploy」
2. 「Edit code」で中身を `tools/proxy-worker.js` に置き換えて「Deploy」
3. 「Settings」→「Variables and Secrets」で次を追加
   - `REINFOLIB_KEY`（Secret）：不動産情報ライブラリの API キー（[API 利用申請](https://www.reinfolib.mlit.go.jp/api/request/)で発行）
   - `ESTAT_APPID`（Secret・任意）：e-Stat のアプリケーション ID
   - `ALLOWED_ORIGINS`（Text）：`https://yusa-san.github.io`（このサイト以外からは使えないようにする）
4. アプリの「データを重ねる」→「不動産情報ライブラリ」に Worker の URL（`https://fieldnote-proxy.<アカウント>.workers.dev`）を入れる

**動作確認**：設定を変えたら、次のコマンドで確認できます（`Origin` を付けないと、ほかのサイトからの利用を防ぐ設定のため 403 になります）。`secrets` で設定の有無、`reinfolib`・`estat` で Worker から各 API に届くか（応答の状態・時間・先頭の内容）が分かります。

```bash
curl -H "Origin: https://yusa-san.github.io" "https://fieldnote-proxy.<アカウント>.workers.dev/health"
```

e-Stat の検索を試すときは、日本語を URL エンコードして送ります。

```bash
curl -G -H "Origin: https://yusa-san.github.io" --data-urlencode "searchWord=人口" --data-urlencode "limit=3" "https://fieldnote-proxy.<アカウント>.workers.dev/estat/getStatsList"
```

うまくいかないときは、Worker の「Logs」でエラーを確認してください。API に届かないときは `{"error":"upstream fetch failed", ...}` が返ります。

API の結果は Cloudflare のキャッシュに 1 日残り、端末にも残るので、同じ場所は 2 回目から速く表示されます。

## 現地で使う道具

- **2 つの地図を比べる**：「地図の切替」→「2 つの地図を比べる」で左右の地図を選びます。境目の丸をドラッグして動かします。今昔マップは、選んでいる地域のすべての時期から選べます
- **標高断面図**：計測（右の定規ボタン）で 2 点以上を置いて「断面図」、または「一覧」の軌跡の「断面」。1m 標高（4 km を超える線は 5m・10m）から最大 300 点を読みます
- **写真をまとめて読み込む**：「保存・設定」→「読み込み」→「写真をまとめて読み込む」。JPEG の位置情報・撮影時刻・撮影方向を使います。iPhone では写真を選ぶ画面の「オプション」で「位置情報」をオンにしないと位置が消えます
- **日の出・日の入り**：ステータス欄の下の段に表示します（端末で計算し、通信しません）

## 複数人で調査する

1. それぞれの端末で「保存・設定」→「保存・印刷」→「ZIP（JSON＋写真）」を保存し、共有します
2. 受け取った側は「読み込み」→「メモ・軌跡を読み込む」でそのファイルを選び、**「ほかの人のデータとして追加」**を選びます（記録者の名前は自動で入ります。変えられます）
   - 自分のメモは上書きしません。取り込んだメモには続きの番号と記録者名が付き、写真・録音・軌跡も一緒に入ります
   - 同じファイルをもう一度取り込んでも二重になりません
3. 取り込むと、ピンの色が記録者別になります。「一覧」の上の切り替えか「設定」→「ピンの色」でカテゴリ別に戻せます。地図の右下の凡例に記録者と件数が出ます

自分の別の端末・バックアップから戻すときは「自分のデータとして統合」を選びます（同じメモは更新日時が新しい方を残します）。

## 位置の補正とピンの手直し

- **ピンを動かす**：ピンをタップ →「位置を直す」。すべてのピンをドラッグで動かせるようになります（「元に戻す」「完了」）。最初の位置（GPS で取った位置）はメモに残り、ポップアップに「位置を手直し済み」と出ます
- **GPS・方位の補正**（現在地ボタンを長押し、または「設定」）：必要なものだけ選べます。補正を促す通知は出しません
  - 位置のずれを直す：地図を動かして十字を本当の位置に合わせると、その差を以後の測位に当てます（解除できます）
  - 測位を平均してメモを作る：「現在地にメモ」で 5〜30 秒の測位を精度で重み付けして平均します
  - 精度の悪い測位を使わない：±15〜100 m より悪い測位を現在地と軌跡に使いません
  - 方位（コンパス）の補正：向きの扇形のずれを ±45° で直します

## 軌跡が途中で止まったとき

記録中の軌跡は 5 秒ごとと、画面が消える・アプリを離れるときに端末へ保存します。電池切れなどで止まった場合は、次に開いたときに軌跡を地図に出し、「続けて記録しますか？」と聞きます（続ける場合、止まっていた間は線をつなぎません）。表示していた軌跡は、開き直しても表示したままになります。

## 地図の印刷・PDF・画像出力

「保存/設定」→「範囲を決めて印刷・PDF・画像に出力」（または「地図の切替」の一番下）で始めます。

1. **設定**：タイトル（任意）・用紙（A5／A4／B4／A3）・向き・縮尺・画質（150／200／300 dpi）・文字と記号の大きさを選びます
   - 縮尺を「1:2,500」などに決めると、その縮尺で用紙に収まる範囲の枠が出ます。「枠の大きさで決める」にすると、地図を拡大縮小して範囲を決め、縮尺はそれに合わせて決まります
2. **範囲を合わせる**：地図の上の赤い枠が印刷範囲です。地図を動かして合わせます
3. **印刷するもの**：いま地図に表示しているレイヤ（背景・重ねる地図・1m標高・PDF/画像の地図）と、軌跡・メモ（タイトルの有無も）から選べます
4. **配置**：方位記号・スケールバーを地図の四隅のどこに置くか（入れないことも可）、凡例を入れるかとその位置。凡例にはメモのカテゴリ（件数）・軌跡・標高の色・重ねた地図の名前が入ります
5. **プレビュー・出力**：PDF を保存／画像（PNG）を保存／印刷する（ブラウザの印刷画面。プリンタのほか「PDF に保存」も選べます）

用紙の下には縮尺・作成日・中心座標と、印刷したレイヤに応じた出典（国土地理院・ハザードマップポータルサイト・OpenStreetMap、重ねた地図の名前と参照 URL）が自動で入ります。縮尺どおりに印刷するには、印刷の倍率を 100%（実際のサイズ）にしてください。端末のメモリに合わせて、大きな用紙・高い画質では自動で少し画質を下げることがあります。

### スタイル JSON を読み込む

「スタイル」の画面の下の「JSON ファイルを選ぶ」（または URL）で、Vector Studio や Maputnik などで作った MapLibre / Mapbox GL のスタイル（version 8）を読み込めます。地理院のベクトルタイル（optimal_bvmap）を使うスタイルなら、XYZ 版・PMTiles 版のどちらを参照していても、このアプリの地理院 Vector と同じタイルで表示します（オフライン保存・印刷も共通）。

- 読み込んだスタイルはこの端末に保存され、プリセットと同じようにカードから切り替え・削除できます
- Vector Studio の「QGIS 用」書き出しのように文字（symbol）のレイヤがないスタイルには、「地理院の注記を重ねる」で地理院の標準の地名・記号を上に重ねられます（初期値はオン）
- 「表示する項目」（道路・鉄道・等高線など）の切り替えも、読み込んだスタイルに効きます

地理院 Vector は MapLibre GL（初回だけ読み込み、約 1MB）で描画します。一度表示した範囲のタイル・スタイル・文字のデータは端末に残り、「表示範囲の地図を端末に保存」も使えます。

## 1m標高（段彩）

「地図の切替」→「標高（1m 標高タイル）」でオンにします。色別標高図（地理院が色を付けた画像）と違い、標高の値そのものを読み込んで端末で色を付けるので、

- **表示中の範囲に色を合わせられる**：平地でも 1〜2m の起伏（自然堤防・旧河道・段丘崖・盛土など）が色の違いとして見えます
- **段彩の間隔を選べる**：0.5m・1m などで区切ると、等高線のように高さの境目が分かります
- **陰影**：1m の標高から計算した陰影を重ねて、微地形を立体的に表示

データは国土地理院の標高タイル（1m：DEM1A、補完に 5m：DEM5A/5B、10m：DEM10B）です。ズーム 17 を超えると 1m の格子を拡大して表示します。凡例をタップすると設定画面が開きます。

## ZIP の中身

```
fieldnote_<調査名>_<日時>/
├── data.json        全データ（下記の形式。写真は "file" で photos/ 内のファイルを参照）
├── memos.geojson    メモの点（properties.photos に写真ファイル名）。QGIS 等でそのまま開ける
├── memos.csv        メモの表（photos 列に写真ファイル名）
├── tracks.gpx       メモ（ウェイポイント）と軌跡
├── audio/           聞き取りの録音（memo001_rec1.webm など）
├── overlays/        PDF から作った地図（位置合わせ済み GeoTIFF・元画像・ワールドファイル）
└── photos/
    ├── memo001_1.jpg
    └── ...
```

ZIP は無圧縮（写真は JPEG なので圧縮してもほとんど縮まないため）。このアプリの「読み込み」に ZIP を渡すと写真ごと復元できます。

Python で読む例：

```python
import json, geopandas as gpd
d = json.load(open("fieldnote_xxx.json", encoding="utf-8"))
gdf = gpd.GeoDataFrame(
    [{k: v for k, v in m.items() if k != "photos"} for m in d["memos"]],
    geometry=gpd.points_from_xy([m["lon"] for m in d["memos"]], [m["lat"] for m in d["memos"]]),
    crs="EPSG:4326",
)
```

## 出典・利用上の注意

- 地図：[国土地理院（地理院タイル）](https://maps.gsi.go.jp/development/ichiran.html)、[国土地理院 最適化ベクトルタイル](https://github.com/gsi-cyberjapan/optimal_bvmap)、[ハザードマップポータルサイト](https://disaportal.gsi.go.jp/)、© OpenStreetMap contributors
- 標高 API・逆ジオコーダ・地名検索：国土地理院
- 旧版地図：今昔マップ on the web（谷謙二）、迅速測図：農研機構農業環境研究部門（歴史的農業環境閲覧システム）
- 気象：気象庁ホームページ（アメダス・降水ナウキャスト）
- 周辺の情報：Wikipedia（CC BY-SA 4.0）・Wikidata（CC0）・ジャパンサーチ
- 緑のオープンデータ：東京都都市整備局「緑のオープンデータ（GISデータ）」（CC BY 4.0）を加工して作成
- 不動産情報ライブラリ（国土交通省）の API を使用（各データの原典の利用条件に従ってください）
- 統計：政府統計の総合窓口（e-Stat）。市区町村界：『歴史的行政区域データセットβ版』（CODH 作成、国土数値情報 行政区域データを加工）
- OpenStreetMap のタイルは利用規約により一括ダウンロード（オフライン保存）の対象外にしています。
- ハザード情報は概略です。詳細は各自治体の公表資料を確認してください。
